# nor-fw：双槽 NOR 闪存固件更新模拟器

纯 Rust、零第三方依赖，模拟一块带两个固件槽的 NOR 闪存及其掉电安全的
A/B 更新与启动选择流程。**不包含**签名体系、真实硬件驱动与联网下载。

## 器件模型

| 项 | 值 |
|---|---|
| 固件槽 | 2 个，各 32 KiB（偏移 0 与 0x8000） |
| 擦除扇区 | 4 KiB（每槽 8 个扇区） |
| 编程页 | 256 字节 |
| 记录区 | 2 个 4 KiB 扇区，循环换代（偏移 0x10000） |
| 器件总大小 | 73 728 字节（18 个扇区） |

NOR 语义被严格建模：擦除后全 `0xFF`；编程只能把位 `1→0`，尝试 `0→1`
直接报 `ProgramConflict`；只有擦除能把位恢复为 `1`。

## 更新包格式

```
0..8   魔数 b"FWPKG001"
8..12  版本（u32 大端，必须相对当前版本递增）
12..16 载荷长度（u32 大端）
16..48 载荷 SHA-256
48..   载荷
```

## 发布记录如何区分「完整发布」与「半包」

记录定长 **104 字节**，布局：

```
0..8    魔数 b"FWREC\0\0\0"
8..16   记录序号 seq（u64 大端，全局单调递增）
16      槽号（0/1）
17..21  版本（u32）
21..25  固件长度（u32）
25..32  保留（0xFF）
32..64  固件载荷 SHA-256
64..96  记录本体（0..64）的 SHA-256
96..104 commit 魔数 b"REC-CMMT"   ← 整个记录最后编程
```

更新顺序是**先数据、后记录、最后 commit**：

1. 只擦除「非当前槽」的 8 个扇区；
2. 按 256 字节页写入新固件（尾页用 `0xFF` 补齐）；
3. **逐字节读回核验**整个槽（载荷 + 填充 + 其余空间）；
4. 读回完全一致后才写发布记录，commit 魔数最后落地。

启动器（`boot::inspect`，纯只读、不依赖任何内存状态）对每个记录槽位：

- commit 魔数不完整 → 未提交，忽略；
- 本体 SHA-256 不符 → 本体被撕碎，忽略；
- 两者都成立 → 完整记录；再对其指向的固件数据做 SHA-256 校验，
  数据损坏（例如槽被部分擦除）同样跳过。

因此固件写一半掉电、记录写一半掉电，都不会被误启动；只有「数据完整且
记录已提交」才会成为候选。候选按 `(换代号, 序号)` 取最新。

## 记录区循环换代如何保护最后可启动版本

每个记录扇区有 120 字节头部（魔数 + 换代号 + 16 字节头部 commit 魔数），
其后容纳 38 条记录。当前扇区写满时：

1. 擦除**另一**个记录扇区，写入 `generation+1` 的头部（commit 最后写）；
2. 把上一代**最新一条完整记录**原样搬运（carry）到新扇区 idx0；
3. 在 idx1 写本次新记录；
4. 两条记录都在新扇区落地后，才擦除旧扇区。

任意一步掉电：

- 新扇区头未激活 → 整个新扇区不被承认，旧扇区完好 → 选旧版本；
- carry / 新记录撕碎 → 旧扇区仍完好 → 选旧版本；
- 新记录已提交、回收旧扇区时掉电 → 新扇区完整 → 选新版本，
  旧扇区的部分擦除垃圾因头部失效被整体忽略。

换代重试时追加器会**越过撕碎槽位**（追加位置 = 最后一个已占用记录的
紧后槽位，而非「第一个看起来空的位置」），不会对 `0` 位重复编程。

## 故障注入

- `--cut-erase=<第次擦除>:<图案>`：擦除中断，留下夹具指定的部分擦除内容
  （`zero` / `keep-head` / `keep-tail` / `checker` / `stripes`），
  而不是干净的 `0xFF`；
- `--cut-page=<页>:<页内字节>`：任一编程页的任一字节后掉电（含填充字节）；
- `--cut-record=<阶段>:<字节>`：发布记录 / 换代头 / carry 记录任一字节后掉电。

掉电时镜像文件保留断点内容，进程退出码 3；重新运行 `boot` 即等价于重开电源。

## 命令

```bash
cargo build --release
B=./target/release/nor-fw

$B factory  flash.img [--len=1024]      # 工厂预置槽0 v1
$B pack     2 300 v2.pkg               # 生成 v2 更新包
$B boot     flash.img [--json]         # 启动检查：槽/版本/序号/换代号/依据
$B status   flash.img                  # 记录区逐条明细
$B update   flash.img --pkg v2.pkg     # 更新（可加切点）
$B replay   [--small|--rollover|--all] [--verbose]
```

退出码：`0` 成功；`2` 用法/更新错误；`3` 掉电（镜像保留断点）；
`4` 无可启动固件；`5` 更新被预检拒绝（版本未递增等，镜像不变）。

## 测试与复演结果

- `cargo test`：10 个单元/集成测试（SHA-256 已知向量、NOR 位语义、
  槽位交替、版本递增、半包隔离、部分擦除、逐字节掉电恢复、换代保护）。
- `cargo run -- replay`（debug 构建实测）：
  - 小固件遍历（7 种跨页尺寸）：**4080** 个切点全部通过；
  - 换代遍历（10 个擦除点 × 5 种图案 + 头 32 字节 + carry 104 字节 +
    新记录 104 字节 + v39→v120 多代循环）：**373** 个切点全部通过。

不变量：每个切点重开后，所选版本只能是**掉电前旧完整版本**或
**已完整提交的新版本**，且槽内数据逐字节吻合；之后一次无故障更新必然
使系统到达新版本。

## 模块划分

- `src/layout.rs`：器件布局、记录/头部编码与校验分类
- `src/sha256.rs`：自包含 SHA-256
- `src/flash.rs`：NOR 模型与掉电夹具
- `src/package.rs`：更新包
- `src/boot.rs`：只读启动检查
- `src/updater.rs`：更新器与换代状态机、工厂预置
- `src/replay.rs`：全切点/换代掉电复演
- `src/main.rs`：CLI
